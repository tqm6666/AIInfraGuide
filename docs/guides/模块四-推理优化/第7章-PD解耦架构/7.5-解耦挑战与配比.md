## 1. 解耦后多出来的复杂度

相对单引擎混合服务，解耦至少新增：

| 挑战 | 具体表现 |
|---|---|
| **双池调度** | 既管 P 队列也管 D 队列，还要管两者之间的交接 |
| **状态迁移** | KV 传输、失败重试、超时与幂等 |
| **一致性运维** | 两池模型版本、量化配置必须匹配 |
| **故障域扩大** | P 正常 D 挂、或传输挂，都要有降级路径 |
| **可观测性** | 需打通 TTFT 分段（排队/算/传/再排队） |

🔑 **核心概念**：解耦把"一个难调度"变成"两个阶段 + 一条传输链"——阶段互扰下降，**系统熵上升**。只有当 Goodput 收益盖过熵增时才值得。

## 2. 配比问题为什么致命

设集群共有 $N$ 张 GPU，分给 Prefill 池 $N_p$、Decode 池 $N_d$，$N_p + N_d = N$（可再留管理节点）。

- $N_p$ 太大：Decode 槽位不够，KV 传入后排队，TPOT/可用性变差，P 侧也会因背压空转。
- $N_d$ 太大：Prefill 能力不足，TTFT 排队，D 侧饥饿。

聚合服务里这种错配被"同一池混跑"掩盖成利用率数字；解耦后错配会**直接打在双 SLO 上**。

⚠️ **注意**：配比不是静态勋章。白天聊天 Decode 重、夜间批处理 Prefill 重，同一配比可能昼夜交替翻车。

## 3. P/D GPU 池配比推导

一个可用的工程推导流程：

### 步骤 A：刻画负载

从日志估计单位时间：

- 到达率 $\lambda$（请求/s）；
- 平均输入长度 $\bar{S}_{in}$、输出长度 $\bar{S}_{out}$；
- 目标 TTFT/TPOT SLO。

### 步骤 B：估计两阶段工作量

粗口径（可替换为实测 profile）：

- Prefill 工作量 $\propto \lambda \times \bar{S}_{in}$
- Decode 工作量 $\propto \lambda \times \bar{S}_{out}$（每输出 Token 一步）

再除以单 GPU（或单 TP 组）在该阶段的可持续处理速率，得到所需并行度。

### 步骤 C：加上传输与冗余

\[
N_p \propto \frac{\text{Prefill 工作量}}{\text{单卡 Prefill 速率}} \times (1 + \text{burst 余量})
\]

\[
N_d \propto \frac{\text{Decode 工作量}}{\text{单卡 Decode 速率}} \times (1 + \text{KV 容量余量})
\]

### 步骤 D：用 Goodput 校准

在候选比例（如 1:1、1:2、1:3）上跑混合压测，选 **Goodput 最高且双 SLO 达标** 的点，而不是选利用率最平均的点。

```text
例：若平均输入 2k、输出 200 Token，Prefill 更吃算力，
    起点可试 Np:Nd ≈ 1:2 或 1:3，再按 P95 校准。
    若 RAG 平均输入 8k、输出 100，则 Np 比例上调。
```

📌 **关键点**：**配比公式给的是搜索起点，压测 Goodput 给的是答案。** 不要把经验比例当成真理。

## 4. 动态负荷与再平衡

生产中更稳妥的做法是"慢变化再平衡"：

1. 监控 P 队列等待、D 队列等待、KV 传输耗时、双 SLO 违约率；
2. 若 TTFT 违约主导 → 扩 P 或缩 D（在总预算内迁移）；
3. 若 TPOT/D 排队主导 → 扩 D；
4. 若传输主导 → 先优化拓扑/后端，而不是盲目加 GPU。

自动迁移 GPU 池属于高阶能力（涉及模型重载或弹性实例）。团队初期可按高峰档位做**分时静态配比**（业务高峰一套、夜间一套）。

💡 **提示**：先做"告警 + 人工改副本数"，再做自动弹性。自动配比在错误指标下会放得很大。

## 5. 何时用、何时不用

**更适合解耦**

- TTFT 与 TPOT 双 SLO 同时紧；
- 负载强混合（长 Prefill + 大量流式 Decode）；
- Chunked Prefill / 优先级调度后 P99 仍差数倍；
- 集群有足够高速互联，KV 传输税可控；
- 团队具备双池运维与分段观测能力。

**更适合继续聚合**

- 离线批处理、单 SLO 或 SLO 很松；
- 请求同质、几乎无长尾 Prefill；
- 网络一般，长 Prompt KV 传输昂贵；
- 集群规模小，拆池后每池并行度不够（例如总共 2～4 卡）；
- 控制面人力不足，稳定性优先。

| 条件 | 倾向 |
|---|---|
| 双紧 SLO + 混合负载 + 好网络 | 解耦 |
| 松 SLO / 同质负载 / 差网络 / 小集群 | 聚合 |
| 昼夜负载结构剧变 | 聚合或自适应统一框架 |

## 6. 决策清单

```text
[ ] 是否已用同引擎手段（Chunked Prefill 等）挖完浅层收益？
[ ] 是否定义了 TTFT/TPOT 分位 SLO 与 Goodput？
[ ] 是否测过代表性 Prompt 的 KV 体积与传输 P95？
[ ] 是否有至少 3 组 Np:Nd 的对比压测？
[ ] 是否具备 P/D/传输分段追踪？
[ ] 是否准备了 D 池满或传输失败时的降级策略？
```

全部打勾再上生产解耦；缺一项就先补课。

## 📝 总结

- 解耦用阶段隔离换来调度、传输、运维上的熵增；要用 Goodput 证明值得。
- **P/D 配比错了会直接双杀 SLO**，需按工作量估算再压测校准。
- 配比应随负载结构演进，传输瓶颈优先于盲目加卡。
- 双紧 SLO、强混合、好网络时用解耦；小集群、差网络、松 SLO 时聚合往往更优。
