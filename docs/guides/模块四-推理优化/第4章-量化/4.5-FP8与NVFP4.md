## 1. 问题：为什么低比特还要浮点
INT8/INT4 可以看成“固定间距的整数格子 × scale”。
同一组中，相邻 code 的实数间距相同。

神经网络张量却可能同时包含：
- 许多接近零的小值；
- 中等范围的主体值；
- 少数跨越多个数量级的值。

浮点用指数改变数量级，用尾数描述该数量级内的位置。
它更像科学计数法：
$$
x\approx(-1)^{sign}\times significand\times2^{exponent}
$$

在相同 bit 数下，浮点通常用不均匀的格子换取更大动态范围：
- 靠近零的可表示间距较小；
- 数值越大，相邻可表示数的绝对间距也越大；
- 相对精度主要受尾数位数控制。

这不表示 FP8 必然比 INT8 准。
若一个张量范围集中，INT8 配合合适 scale 可能使用更多等距有效格子。
浮点的优势是更自然地覆盖多数量级，而不是在所有分布上拥有更小误差。

低比特浮点同样需要回答四层问题：
数值格式是什么、scale 怎样共享、Tensor Core 是否原生支持、服务关键路径是否真的受益。

## 2. 符号、指数与尾数
一个典型二进制浮点数包含：

```text
sign | exponent | mantissa
```

对正常数，可抽象为：
$$
x=(-1)^s\left(1+\frac{f}{2^M}\right)2^{e-B}
$$
其中：
- $s$ 是符号位；
- $e$ 是指数编码；
- $B$ 是 exponent bias；
- $f$ 是尾数字段的整数值；
- $M$ 是尾数位数。

指数位更多，通常能覆盖更大的数量级范围。
尾数位更多，同一数量级内的格点通常更密。

在 binade $[2^k,2^{k+1})$ 中，相邻正常数的间距约为：
$$
\operatorname{ULP}=2^{k-M}
$$
若采用最近邻舍入，正常数区域内的绝对误差通常不超过约半个 ULP。

这说明浮点误差与幅值相关。
同一个格式在 1 附近和 128 附近的绝对刻度不同。

指数全零或全一时还可能表示：
- zero 与 signed zero；
- subnormal；
- infinity；
- NaN；
- 或格式专门定义的扩展有限数。

不同 FP8/FP4 变体会重新分配这些编码。
所以只写 `E4M3` 或 `FP4` 仍不足以确定最大值、NaN 和 subnormal 语义。

本节关注范围、精度、scaling 和硬件，不展开 bit-level 编码与 swizzle 规范。

## 3. E4M3 与 E5M2
FP8 总共 8 bit，常见两类分配是：

```text
E4M3：1 sign + 4 exponent + 3 mantissa
E5M2：1 sign + 5 exponent + 2 mantissa
```

总位宽固定，因此多一个指数位就少一个尾数位。

### 3.1 E4M3
E4M3 在每个数量级内有更多尾数格点，局部相对精度较好。
其指数范围小于 E5M2。

在《FP8 Formats for Deep Learning》定义的常见 finite-oriented E4M3 中，最大有限值为 448。
具体框架还可能提供 `fn`、`fnuz` 等变体，范围和特殊值语义不能只靠简称推断。

### 3.2 E5M2
E5M2 用更多指数位覆盖更大动态范围，常见定义的最大有限值为 57344。
但它只有 2 个显式尾数位，同一区间内的格点更稀。

### 3.3 选择不是按“数值更大”排序
可概括为：

```text
E4M3：更多局部精度，较小指数范围
E5M2：更大指数范围，更少局部精度
```

训练中常把 E4M3 用于前向、E5M2 用于动态范围更大的梯度，但这不是推理接口的通用硬规则。
推理 checkpoint、激活和 KV Cache 采用哪种变体，应以目标工具链和 Kernel 合同为准。

无论哪种 FP8，累加通常使用更高精度。
更高精度累加能保护长点积，但无法恢复输入量化时已经丢失的信息。

## 4. 一个 FP8 数值手算
用简化的 E4M3 正常数解码建立直觉，设 bit pattern 为：
```text
0 | 1000 | 010
```
采用 bias $B=7$：sign $s=0$，exponent field $e=8$ 对应真实指数 1，mantissa field $f=2$ 表示 $2/8$。
代入可得：
$$
x=(-1)^0\left(1+\frac28\right)2^1=1.25\times2=2.5
$$
在真实指数 $k=1$ 的区间 $[2,4)$ 中，E4M3 的 ULP 为 $2^{1-3}=0.25$。
所以该区间的正常格点包括 2.0、2.25、2.5、2.75 等。
2.6 的最近格点是 2.5，误差为 0.1；表示 20 附近的数时，绝对格点间距会随数量级增大。
这和 affine INT8 的固定实数间距不同。
但实际 FP8 张量通常还要乘 scale，下一节才是工程中真正使用的网格。

## 5. FP8 为什么仍需要 scale
FP8 自带指数，不代表它能无条件覆盖任意张量。
若张量最大值远超格式范围会溢出；若整体太小，大量值可能落到低精度或下溢区域。

常见 scaled FP8 写成：
$$
q_i=\operatorname{FP8}(x_i/s)
$$
$$
\hat x_i=sq_i
$$

scale 的目标是把该组张量映射到 FP8 的有效范围。
一个简单的最大值缩放是：
$$
s=\frac{\max_i|x_i|}{x_{\max}^{\text{FP8}}}
$$
实际算法也可能保留 margin、使用历史统计或优化误差，而不只贴住最大值。

scale 粒度可以是：
- per-tensor；
- per-row/per-token；
- per-channel；
- per-block；
- 不同实现定义的二维 tile。

粒度越细，越能适应局部范围，但 scale 元数据和在线归约越多。
若激活 scale 动态计算，还要把 `amax` 归约和转换放进关键路径。

所以 FP8 的完整格式不是一个 8-bit code，而是：

```text
FP8 codes + scale 语义 + scale dtype + 共享粒度 + 计算/累加合同
```

## 6. Block scaling：让小格式适应局部范围
位宽降到 4 bit 后，单个元素可用的指数和尾数都极少。
仅靠全张量一个 scale，很难同时覆盖不同局部范围。

Block scaling 把张量切成小块，每块共享 scale：
$$
x_i\approx s_b p_i,\qquad i\in\text{block }b
$$
其中 $p_i$ 是低比特浮点元素，$s_b$ 提供该块的外部数量级。

它相当于两级表示：
1. 元素级 FP4 code 描述块内相对大小；
2. 块级 scale 把整个 codebook 移到合适数量级。

块越小：
- 局部范围更一致；
- outlier 影响的元素更少；
- scale 元数据占比更高；
- Kernel 需要更频繁地加载和应用 scale。

若每 $G$ 个 4-bit 元素共享一个 $b_s$-bit scale，只计第一层 scale：
$$
b_{\text{effective}}=4+\frac{b_s}{G}
$$

例如 32 个元素共享 8-bit scale：
$$
b_{\text{effective}}=4+\frac8{32}=4.25\ \text{bit}
$$
相对 BF16 的数据与首层 scale 理论比为：
$$
\frac{16}{4.25}\approx3.76
$$

若 16 个元素共享 8-bit scale：
$$
b_{\text{effective}}=4.5\ \text{bit},\qquad
\frac{16}{4.5}\approx3.56
$$

这还没计第二级 scale、padding、未量化层和布局元数据。
因此“FP4 模型严格缩小四倍”同样不成立。

## 7. MXFP4 与 NVFP4 的概念边界
MXFP4 与 NVFP4 都使用“低比特元素 + 小块共享 scale”的思想，但不是同一个格式名。

### 7.1 MXFP4
MXFP4 属于 OCP Microscaling Formats 规范族。
其核心组合是：
- 块内 FP4 E2M1 元素；
- 通常 32 个元素共享一个 E8M0 scale；
- E8M0 scale 以指数形式提供 2 的幂缩放。

E8M0 的 power-of-two scale 便于硬件实现，但 scale 本身只能落在离散指数格点。
这会产生“元素舍入 + scale 舍入”两层误差。

### 7.2 NVFP4
NVFP4 是 NVIDIA 面向 Blackwell FP4 路径提出的数值与 scaling 方案。
其核心组合可概括为：
- 块内 FP4 E2M1 元素；
- 更小的 16-element block；
- 每块使用 FP8 E4M3 scale；
- 再配合更高层的全张量 scale。

更小 block 和更细的 E4M3 scale 能更贴近局部范围，代价是更多 scale 元数据和更复杂的两级缩放。

### 7.3 不能互换名称
二者差异至少包括：
- block size；
- block scale 的数值格式；
- 是否以及怎样使用第二级 scale；
- 量化网格和可表达范围；
- 硬件指令与 Kernel 接受的布局。

一个标为 MXFP4 的 checkpoint 不能因为元素同为 E2M1，就直接当作 NVFP4 输入。
元素 code 相同也不代表 scale 语义和张量布局相同。

本章只保留这些影响数值与选型的概念，不把章节写成编码、packing 或 swizzle 规范手册。

## 8. Ada、Hopper 与 Blackwell 的硬件前提
### 8.1 Ada 与 Hopper：都进入原生 FP8 可行域
NVIDIA Ada Lovelace（SM 8.9）与 Hopper 都提供原生 FP8 Tensor Core 矩阵计算路径；Hopper 还面向数据中心训练与推理强化了 Transformer Engine、带宽和并行能力。不能把“原生 FP8”写成 Hopper 独有的代际边界。

这使 E4M3/E5M2 不再只是压缩存储格式，而能进入硬件加速的 GEMM。
但收益仍要求：
- 框架生成受支持的 FP8 操作；
- shape、布局与对齐匹配 Kernel；
- scale 管理没有主导关键路径；
- 未量化算子占比可控。

在没有原生 FP8 Tensor Core 的更早 GPU 上，FP8 checkpoint 可能被转换、展开或走兼容路径。
文件可加载不等于设备能按 FP8 峰值计算。

### 8.2 Blackwell：原生 FP4 路径
NVIDIA Blackwell 的第五代 Tensor Core 与第二代 Transformer Engine 扩展了 FP4/microscaling 低精度能力，NVFP4 的主要硬件落点在这一代。

这意味着讨论 NVFP4 端到端加速时，Blackwell 级硬件是基本前提。
在 Hopper 上保存 FP4 codes 并不能凭空得到 Blackwell 的 FP4 Tensor Core 路径。

MXFP4 是开放 microscaling 规范中的格式。
某个 Blackwell 软件栈是否直接支持特定 MXFP4 checkpoint，仍应分别核对框架、库和 Kernel；不能从“硬件支持 FP4”推导所有 FP4 布局都兼容。

### 8.3 硬件代际只是必要条件
GPU 支持一种指令，不表示模型每层都会使用它。
MoE、Attention、Norm、Embedding、Sampling、通信和不规则小矩阵都可能采用其他 dtype 或路径。

硬件能力回答“有没有可能”，Kernel coverage 才回答“多少关键路径兑现”。

## 9. Kernel 怎样兑现低精度浮点
一个 scaled FP8 GEMM 可抽象为：
```text
高精度或 FP8 输入
→ 按约定得到/读取 scale
→ 转换并读取 FP8 A、B
→ FP8 Tensor Core multiply
→ 更高精度 accumulate
→ 在 epilogue 应用输出 scale / bias / activation
```
FP4 block-scaled GEMM 还要：
- 按 block 读取 scale；
- 在正确 tile 上广播并处理两级 scale；
- 让 packed FP4 与 Tensor Core fragment 对齐。

高性能实现会把 scale 应用、转换和 epilogue 尽可能融合。
若单独写出完整反缩放张量，HBM 流量会侵蚀压缩收益。
Kernel 的数值合同至少包含输入、scale、乘法、累加与输出 dtype。

还要区分 Weight-only FP8、FP8 weight + activation、FP8 KV、FP4 weight-only 和 FP4 weight + activation。
它们可能共享格式名称，却改变不同的 HBM 与计算项。

## 10. Prefill、Decode 与端到端上限
### 10.1 Prefill
Prefill 形成大 GEMM，权重被许多 token 复用，常更接近计算受限。
若权重和激活都进入原生 FP8/FP4 Tensor Core，低精度峰值更有机会转为 Prefill 吞吐和 TTFT 改善。

动态 activation scaling、格式转换和非 GEMM 算子仍会占时间。
Prompt 越短或矩阵越小，固定成本越难摊薄。

### 10.2 Decode
小 batch Decode 更常受权重带宽限制。
FP8 权重相对 BF16 少约一半 raw 字节，FP4 更少，因此也可能改善 TPOT。

但若每步还要动态量化激活，或小 GEMM 不能高效使用 Tensor Core，计算峰值优势可能无法体现。
成熟 W4A16 Kernel 有时更直接，选择要看真实 batch 与硬件。

长上下文 Decode 还可能由 KV 读取和 Attention 主导。
只量化 Linear 权重不会减少 BF16 KV 流量。

### 10.3 纸面 FLOPS 为什么不是服务吞吐
即使某低精度峰值是 BF16 的数倍，端到端加速仍受 Amdahl 定律约束。
若可加速 GEMM 只占基线时间比例 $p$，该部分加速 $s$ 倍，则：
$$
S_{\text{e2e}}\leq
\frac{1}{(1-p)+p/s}
$$

例如 GEMM 占 70%，即使它加速 4 倍：
$$
S_{\text{e2e}}\leq\frac1{0.3+0.7/4}\approx2.11
$$
这还没加入 scale、转换和调度开销。

峰值表还可能采用特定 dense/sparse 定义、理想 shape 和高功耗状态。
线上 TTFT、TPOT 与 Goodput 不能由一项峰值 TFLOPS 直接换算。

## 11. 精度、容量与选择
### 11.1 7B/70B 权重下界
7B/70B 的 FP8 raw 权重约为 7/70 GB，FP4 raw codes 约为 3.5/35 GB。
若计入 block scale，实际位宽至少高于 4 bit；NVFP4 还包含第二级 scale。
这些只是权重项，KV Cache、未量化层、workspace、通信和图捕获仍需另算。

### 11.2 精度风险
E4M3/E5M2 的风险来自溢出、下溢和有限尾数。
FP4 再加入极少元素格点、block outlier 和 scale 量化误差。
质量判断应覆盖：
- 数值饱和、NaN/Inf 与异常输出；
- 层重建和任务指标；
- 代码、数学、长上下文等敏感子集；
- 多轮采样路径，以及保留高精度层后的真实平均位宽。

### 11.3 选择顺序
1. 若 GPU 是 Ada 或 Hopper，且 Prefill GEMM 为主要瓶颈，优先评估该 GPU、模型和软件栈覆盖的成熟 FP8 路径；
2. 若 GPU 是 Blackwell，才把原生 NVFP4/MXFP4 路线纳入计算加速候选；
3. 若主要问题是 Decode 权重带宽，也要与成熟 W4A16 比较；
4. 若主要问题是 KV 容量，应选择 FP8 KV 或专门 KV 方法，而不是只改权重；
5. 若格式、Kernel 或质量任一不满足，BF16/FP16 仍是正确基线。
最终证据顺序是：硬件能力 → 格式与 Kernel 可用 → 数值/质量通过 → 端到端 SLO 改善。

## 总结
低比特浮点用指数换取动态范围，用尾数决定局部精度；scaled FP8 和 block-scaled FP4 还通过外部 scale 调整张量范围。

E4M3 与 E5M2在范围和精度间取舍。
MXFP4 与 NVFP4 都使用 E2M1 元素和块级缩放，但 block、scale 格式与层级不同，不能混用。

Ada 与 Hopper 都为原生 FP8 提供硬件路径，Blackwell 才是本章 FP4 计算路线的主要落点。
纸面 FLOPS 只有在格式、Kernel、shape 和端到端关键路径共同匹配时才会兑现。
