## 本章简介

前三章解决的是"请求怎么装进显存、怎么喂饱 GPU"。本章换一条杠杆：**用更少比特表示权重、激活或 KV**，在可接受误差内换取容量与吞吐。机制上不再重复 PagedAttention / 调度细节，只在需要时挂接第 2–3 章；重点放在定标与粒度、各条量化路线的代价，以及 vLLM 上的选型与验收。

**量化基础**钉死仿射映射、对称/非对称、Per-tensor/channel/group，并用 INT8/FP16 显存与带宽粗算区分"省存储"与"真加速"。

**W8A8 与 SmoothQuant**解释 Activation Outlier 为何绑架激活 scale，以及等价变换为何能把难度迁到权重；同时划清适用边界（何时不如直接上 FP8 或 INT4）。

**Weight-only INT4**对比 GPTQ 与 AWQ 的差异与"何时选谁"，并强调 Marlin 等 Kernel / 打包开销决定 4-bit 能否变成真实 Decode 加速。

**KV Cache 量化**用手算容量公式说明长上下文为何被 KV 卡住，讨论精度敏感点与和权重量化叠加的风险；工程落点以 FP8 KV 为主，KIVI 提供极低比特直觉。

**FP8 与 NVFP4/MXFP4**写清 Hopper/Blackwell 硬件前提，并明确：纸面 FLOPS 不是业务 tok/s。

**选型与 vLLM 实战**给出可执行决策树，加上精度探针与吞吐/容量的最小验收，避免营销式横向对比。

## 本章章节

- **4.1 量化基础**：定标、对称/非对称、粒度、PTQ/QAT，以及 INT8/FP16 粗算
- **4.2 W8A8 与 SmoothQuant**：Outlier 直觉、难度迁移、适用边界
- **4.3 Weight-only INT4**：GPTQ vs AWQ、Kernel/打包、显存账
- **4.4 KV Cache 量化**：容量手算、敏感点、FP8 KV 与叠加风险
- **4.5 FP8 与 NVFP4/MXFP4**：硬件前提、格式选择、勿误读峰值 FLOPS
- **4.6 量化选型与 vLLM 实战**：决策树 + 精度探针/吞吐验收
