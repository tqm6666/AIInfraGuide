## 1. 问题：Decode 为什么值得只压权重
自回归 Decode 每个序列每步通常只新增一个 token。
小 batch 时，一个 Linear 仍要读取大部分权重，却只完成少量 token 的矩阵乘。

第 1 章的 Roofline 近似为：
$$
P=\min(P_{\text{peak}},BW_{\text{HBM}}\times I)
$$
当算术强度 $I$ 很低时，提高峰值算力帮助有限，减少 HBM 字节更直接。

Weight-only INT4 的目标因此很具体：
- 权重以 4-bit codes 常驻；
- 激活保持 FP16/BF16；
- 读取权重时在 Kernel 内解包、缩放；
- 尽量不把完整反量化权重写回 HBM；
- 用较高精度完成乘法或累加。

常写成 **W4A16**：权重约 4 bit，激活约 16 bit。
这里的 16 可能是 FP16 或 BF16，实际计算与累加 dtype 必须继续说明。

它不是“整个模型都以 INT4 做整数运算”。
Weight-only 的核心价值首先来自权重压缩和带宽，而不是四位整数 Tensor Core 峰值。

## 2. W4A16 的真实数据路径
对线性层：
$$
Y=XW
$$
量化 checkpoint 保存的通常不是 $\hat W$ 的高精度副本，而是 $Q_W,S_W$、可选的 $Z_W$ 与布局元数据。
逻辑计算为：
$$
\hat Y=X\operatorname{DQ}(Q_W,S_W,Z_W)
$$

低效实现可能先执行：

```text
INT4 weight → 完整 BF16 weight → 写回 HBM → 普通 GEMM
```

这样虽然磁盘文件小，运行时仍会读取展开后的权重，甚至多一次转换和写回。

融合 Kernel 的目标是：

```text
HBM 中的 packed INT4
  → tile 级读取
  → 在寄存器/共享内存中解包
  → 读取该 group 的 scale
  → 局部恢复为计算所需表示
  → 与 FP16/BF16 activation 相乘
  → 较高精度累加与 epilogue
```

反量化没有消失，只是被移到靠近消费位置，并与矩阵乘流水线重叠。
性能收益要求：
$$
\text{少读权重的时间}
>
\text{解包、scale 读取、转换与额外调度时间}
$$

若 Kernel 不能融合，W4A16 可能只带来容量收益。

## 3. Group-wise INT4 手算
采用对称 INT4，使用 $[-7,7]$ 作为教学范围。
一组权重为：

```text
w = [-1.0, -0.4, 0.2, 0.9]
```

该 group 的 scale：
$$
s=\frac{\max|w|}{7}=\frac17\approx0.142857
$$

逐个量化：
$$
q_1=\operatorname{round}(-1.0/s)=-7
$$
$$
q_2=\operatorname{round}(-0.4/s)=-3
$$
$$
q_3=\operatorname{round}(0.2/s)=1
$$
$$
q_4=\operatorname{round}(0.9/s)=6
$$

反量化后：

```text
q    = [-7, -3, 1, 6]
what = [-1.0000, -0.4286, 0.1429, 0.8571]
```

对应误差 $w-\hat w$ 约为：

```text
[0, 0.0286, 0.0571, 0.0429]
```

若另一个局部 group 的范围只有 0.1，它可以使用约 $0.1/7$ 的细刻度。
若两个 group 被合并，小范围权重就必须沿用 1.0 决定的粗刻度。

这解释了 group size 的精度作用。
但 group 越小，scale 数量越多，Kernel 切换 scale 的频率也越高。

假设每 128 个 INT4 codes 共享一个 FP16 scale，不计 zero-point：
$$
b_{\text{effective}}=4+\frac{16}{128}=4.125\ \text{bit/weight}
$$
7B 权重本体约为：
$$
7\times10^9\times\frac{4.125}{8}\approx3.61\ \text{GB}
$$
70B 约为 36.1 GB。
它们仍未计入对齐、未量化层和运行时其他状态。

## 4. GPTQ：用输入相关的二阶信息补偿误差
仅最小化每个权重的 $(w-\hat w)^2$ 会忽略一件事：
权重是否重要，取决于它乘到什么输入。

对一层校准输入 $X$ 和权重 $W$，GPTQ 关注层输出重建：
$$
\mathcal{L}(\hat W)=\|XW-X\hat W\|_F^2
$$
令 $\Delta W=\hat W-W$，则：
$$
\mathcal{L}=\|X\Delta W\|_F^2
$$
对单个输出列，其二阶结构由输入相关矩阵决定：
$$
H\propto X^\top X
$$

直觉上：
- 某输入方向经常被强烈激活，沿该方向的权重误差影响更大；
- 输入通道彼此相关时，一个权重的误差可由尚未量化的权重部分补偿；
- 量化顺序和误差传播方式会影响最终层输出。

GPTQ 按块处理权重。
当一个列或坐标被舍入到量化格点后，它不只记录误差，还借助近似的逆 Hessian 信息调整剩余未量化坐标，使校准输出变化尽量小。

可以把过程理解为：

```text
量化当前坐标
→ 计算该坐标误差
→ 根据输入相关性，把可补偿部分分配给未量化坐标
→ 继续下一坐标
```

它比逐元素 nearest rounding 多使用了“哪些输入方向敏感”和“误差可怎样转移”的信息。

本章不展开完整 OBS 推导。
选型所需的关键结论只有三个：

1. GPTQ 是训练后、以层输出重建为目标的 weight-only 方法；
2. Hessian 近似来自校准输入，因此校准分布会影响结果；
3. 算法生成的顺序、分组和索引必须被运行时格式与 Kernel 理解。

二阶方法不保证全模型任务指标最优。
局部层重建仍只是生成质量的代理目标。

## 5. AWQ：由激活识别重要权重
AWQ 的出发点同样是：
权重绝对值小，不代表它对输出不重要。

对于输出贡献：
$$
y_i=\sum_j x_jw_{ji}
$$
若输入通道 $x_j$ 经常很大，连接该通道的权重即使不大，其量化误差也可能被放大。

AWQ 用少量代表性激活识别更重要的权重通道，并搜索按通道缩放，使这些权重在 group-wise 低比特量化中获得更好的有效分辨率。

一种理解方式是插入等价缩放：
$$
XW=(XS^{-1})(SW)
$$
若某输入通道重要，适当放大 $SW$ 中对应权重，再进行 group-wise 量化，可让它相对共享 scale 占据更多格子。
同时 $XS^{-1}$ 保持浮点函数等价。

与 SmoothQuant 相似之处是两者都利用通道缩放重新分配量化难度。
目标却不同：
- SmoothQuant 主要为 W8A8 平滑激活离群通道；
- AWQ 主要为 W4A16 保护 activation-aware 的重要权重。

缩放也不是免费精度。
一个通道被放大后，可能扩大所在 group 的动态范围并伤害其他权重。
AWQ 因而要搜索折中，而不是无限放大重要通道。

AWQ 不需要在服务时保留完整校准激活。
激活统计用于离线选择权重缩放，运行时通常仍只量化权重。

## 6. GPTQ 与 AWQ 的共同点和差异
共同点：
- 都是面向已有模型的 PTQ；
- 都用校准激活，而不只看权重直方图；
- 都常生成 group-wise INT4 权重；
- 都需要格式、packing 和高性能 Kernel 配合；
- 都不能由局部误差直接保证业务质量。

核心直觉差异：

```text
GPTQ：当前权重舍入后，怎样用二阶相关性补偿误差？
AWQ：哪些权重因输入激活而重要，怎样在量化前保护它们？
```

GPTQ 的主要附加复杂度来自 Hessian 近似、顺序量化和补偿。
AWQ 的主要附加复杂度来自 activation-aware 缩放搜索。

二者名称不能单独决定优劣。
实际结果还取决于：
- 模型架构和层敏感性；
- 校准样本；
- 位宽、group size 与 zero-point 约定；
- 是否使用 act-order；
- 运行时采用哪个 Kernel；
- Prefill/Decode 比例与 batch shape。

“GPTQ checkpoint”或“AWQ checkpoint”也不是唯一二进制格式。
同一算法可以导出不同布局，同一布局也可能容纳不同算法得到的权重。

## 7. Group size、act-order 与 packing
### 7.1 Group size
group size $G$ 控制每个 scale 覆盖多少权重。

```text
G 小：局部拟合通常更好，scale 更多，元数据与调度更复杂
G 大：布局与元数据更规整，不同范围共享刻度，误差可能更大
```

还要明确 group 沿输入维还是输出维。
Tensor Parallel 切分后，group 边界能否落在每个 shard 内，也会影响加载和 Kernel。

### 7.2 Act-order
GPTQ 中常见的 activation order 会优先处理二阶统计上更敏感的输入通道。
目标是减少重要方向被后续误差污染。

若物理列顺序发生变化，checkpoint 可能需要保存映射索引，例如某类 `g_idx` 语义。
运行时按索引重排会增加间接访问，某些 Kernel 只支持静态分组或受限的 act-order 组合。

因此 act-order 可能改善精度，也可能缩小高性能 Kernel 可用集合。
这是算法精度与系统规则性的典型交换。

### 7.3 Packing
两个 4-bit code 可装进一个 byte，但“装得下”不等于“布局相同”。
格式至少要约定：
- signed/unsigned code 解释；
- 高低 nibble 顺序；
- zero-point 是否存在、如何编码；
- scale dtype 与存放顺序；
- group 轴和矩阵转置；
- tile interleave、padding 与对齐；
- 并行 shard 如何切分。

一个 INT4 checkpoint 能被加载，只说明 loader 识别了某种格式。
要得到速度，还要让布局符合 Kernel 期望，或在加载时完成一次不会破坏语义的预打包。

## 8. Marlin 类 Kernel 怎样兑现压缩
Marlin 类 W4A16 Kernel 的核心目标不是消灭反量化，而是把它隐藏在高吞吐矩阵乘的数据供给中。

一个 tile 的工作可抽象为：
1. 合并读取 packed INT4 权重；
2. 解包并应用 group scale；
3. 将权重转换成 Tensor Core 可消费的表示；
4. 与 FP16/BF16 激活形成矩阵乘流水线；
5. 使用更高精度累加；
6. 融合输出转换与 epilogue。

为了做到这一点，Kernel 通常对以下因素敏感：
- $M,N,K$ 的大小和对齐；
- group size 与 scale 布局；
- act-order/索引形式；
- GPU 架构与可用指令；
- 并发 batch 和 split-K 等调度选择；
- Tensor Parallel 后每个 rank 的局部 shape。

压缩权重减少 HBM 请求，但解包会增加指令和寄存器压力。
若预打包布局让读取不连续，或 scale 访问成为瓶颈，理论四倍字节差距不会完整转化为加速。

高性能路径尤其要避免：
$$
\text{packed INT4}\rightarrow\text{完整 FP16 权重写回 HBM}
$$
正确方向是让恢复后的短生命周期 tile 留在片上并立即被消费。

“Marlin 类”在本章表示这种融合设计思想，不表示所有引擎、GPU 和 shape 都使用同一实现。

## 9. Prefill 与 Decode 的收益边界
### 9.1 Decode：最匹配权重带宽问题
小 batch Decode 的 Linear 常接近 GEMV 或小 GEMM。
权重几乎每步都要搬一遍，复用有限。

从 BF16 的 16 bit 到 INT4 的 4 bit，codes 的理论读取量降到四分之一。
但真实读取还包括 scales、zero-points、对齐和未量化层，Kernel 还有解包成本。

因此可期待的是“显著减少权重流量的机会”，不是无条件四倍 TPOT 改善。
当权重带宽占每步时间比例越高，W4A16 的上限越有吸引力。

### 9.2 Prefill：大矩阵可能转为计算受限
Prefill 中许多 token 复用相同权重，权重读取被更多 FLOPs 摊薄。
W4A16 Kernel 通常恢复到较高精度参与计算，并不必然获得真正 4-bit×4-bit 的计算峰值。

若 Prefill 已是计算受限，减少权重 HBM 字节的边际收益会变小，解包指令反而可能限制吞吐。
此时 W8A8 或原生 FP8 路径可能更直接地提高矩阵计算吞吐。

### 9.3 Batch 改变拐点
连续批处理增大 Decode 的 $M$，提高权重复用和算术强度。
某个 Kernel 在 batch 1 很快，不保证在 batch 64 仍领先；反之亦然。

应分别看：
- TTFT 对应的 Prefill shape；
- TPOT 对应的 Decode shape；
- 混合批次和真实输入/输出长度；
- 多卡切分后的局部矩阵；
- 非 Linear、Attention 与通信所占时间。

Weight-only 是局部线性层优化，端到端收益受 Amdahl 定律约束。

## 10. 精度、容量与选型
### 10.1 容量账
7B/70B 的 raw INT4 codes 约为 3.5/35 GB。
加上每组 FP16 scale 后，group size 128 的教学下界约为 3.61/36.1 GB。

进程显存还包括 KV Cache、激活、CUDA Graph、workspace、通信 buffer 和 allocator 余量。
因此“70B INT4 权重约 36 GB”不能推出“40 GB GPU 一定可服务 70B”。

### 10.2 精度账
更小 group、GPTQ 补偿、AWQ 缩放都可能降低权重量化误差，但代价不同。
应关注：
- 层输出重建；
- perplexity 或任务指标；
- 数学、代码、长上下文等敏感子集；
- 输出头或敏感层是否保留高精度；
- 校准分布外行为。

### 10.3 选择顺序
先问：
1. 当前是否由 Decode 权重带宽或权重容量限制？
2. 目标 GPU 和引擎有哪些成熟 W4A16 Kernel？
3. 这些 Kernel 支持哪些 group size、zero-point、act-order 和 TP shape？
4. 在可用格式集合中，GPTQ 与 AWQ 哪个通过质量门槛？

这比先选择论文名称、再强迫运行时适配更稳妥。
格式与 Kernel 是硬约束，算法是在可用集合内争取质量。

组合 KV Cache 量化会再加入一类独立误差和 Kernel 条件。
组合选择留到 4.6；生产性能与灰度方法回指第 9～11 章。

## 总结
W4A16 通过压缩固定权重，主要改善容量和 Decode 的权重读取带宽。
高性能实现必须在 tile 内解包与缩放，避免完整反量化权重回写 HBM。

GPTQ 用输入相关的二阶结构补偿顺序量化误差；AWQ 用激活统计识别并保护重要权重。
group size、act-order、packing 和 Marlin 类 Kernel 把算法精度与系统性能连接起来。
