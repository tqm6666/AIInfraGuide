## 1. 问题与概率起点

### 1.1 Logits 不是概率

第 $t$ 步模型输出：
$$z_t\in\mathbb R^{|V|}$$
$z_t(i)$ 是 Token $i$ 的 Logit，只表示相对分数。
Softmax 才把有限分数归一化为概率：
$$p_t(i)=\frac{\exp z_t(i)}{\sum_j\exp z_t(j)}$$

数值实现通常先减去最大值，避免指数溢出：
$$p_t(i)=\frac{\exp(z_t(i)-m)}{\sum_j\exp(z_t(j)-m)},\qquad m=\max_jz_t(j)$$

随后选择一个 Token，追加到序列，更新 KV、Grammar 和 RNG，再进入下一步。
一次前向不会直接吐出“一个词”。

### 1.2 $P$ 是完整策略，不是一个参数

统一合同中的 $P$ 至少应固定：
- Processor 顺序、硬约束、停止规则与 Greedy/随机模式；
- Temperature、Top-k、Top-p 和所有默认值；
- Seed、RNG 算法、候选流与分支规则；
- Logprob 阶段、分支得分、长度处理与终止。

只记录 `temperature=0.7` 不足以重放一次生成。
上游默认值或 Processor 顺序变化，也会改变最终分布。

`ops-a` 的事故状态可使用近确定策略，解释摘要则可受控随机；两者的 $P$ 不同。

## 2. Logit Processor 的顺序

### 2.1 Processor 是有序函数组合

设原始 Logits 为 $z^{(0)}$，一组 Processor 为 $f_1,\ldots,f_m$：
$$z^{(j)}=f_j(z^{(j-1)},x_{<t},\text{state})$$
最终选择分布来自 $z^{(m)}$。

典型步骤包括：
```text
原始 Logits -> 分数偏置/惩罚 -> 其他硬支持集 -> 结构支持集
 -> Temperature -> Top-k/Top-p -> 归一化与选择
```

这是用于推理的语义顺序，不代表所有实现都按独立 Kernel 执行。
实现可以融合或安全重排，但结果必须与声明的 $P$ 等价。

### 2.2 顺序通常不可交换

一般有：
$$f_a(f_b(z))\neq f_b(f_a(z))$$

例如先施加重复惩罚，某个 Token 可能跌出 Top-k；先 Top-k 再惩罚，它仍留在候选中。
Top-p 的集合依赖当前归一化概率，所以 Temperature 放在前后也可能改变集合大小。
先 Top-p 截断再做结构 Mask 甚至可能删掉全部合法 Token。
正确实现应先确保硬合法支持集，再在其中截断，或使用可证明等价的融合算法。

### 2.3 支持集视角

设 $C_t$ 为结构合法集合，$H_t$ 为其他硬规则允许集合。
若顺序是 Top-k → Top-p，$K_t$ 先从 $C_t\cap H_t$ 产生，$N_t$ 再从 $C_t\cap H_t\cap K_t$ 的重归一化概率产生。
最终支持集为：
$$S_t=C_t\cap H_t\cap K_t\cap N_t$$
顺序反转时 $K_t,N_t$ 的定义也随之改变，交集写法不代表两者可交换。

最终分布可概念化为：
$$q_t(i)\propto \exp(g_t(z_t(i))/T)\,\mathbf{1}[i\in S_t]$$
$g_t$ 表示前序分数变换。

硬正确性不变量是：
$$\operatorname{support}(q_t)\subseteq C_t$$
本节使用该集合，不重新讲 Grammar 如何得到它。

### 2.4 分数变换与硬删除

Temperature 和多数惩罚只改分数；bad-token、最小长度、结构 Mask 与截断会把概率变为零。
低分仍可能被采样，硬 Mask 则绝不允许；多个硬集合还可能求交为空。
因此降低 Temperature 不能替代禁止非法 Token。

## 3. Greedy、Temperature、Top-k 与 Top-p

### 3.1 Greedy

Greedy 在全部 Processor 之后选择最高分：
$$x_t=\arg\max_{i\in S_t}z_t^{(m)}(i)$$
它不主动维护随机候选，适合需要稳定局部选择的阶段。
Greedy 只保证局部最高分；接近或并列时，浮点误差与 tie-break 仍可能改变选择。

### 3.2 Temperature

当 $T>0$：
$$p_i(T)=\frac{\exp(z_i/T)}{\sum_j\exp(z_j/T)}$$
$T<1$ 放大分数差距，使分布更尖。
$T>1$ 缩小差距，使长尾更容易被采样。
$T$ 不改变排序，也不会单独删除候选。
数学上不能直接代入 $T=0$；工程中通常将其定义为 Greedy 特殊分支。

### 3.3 Top-k

Top-k 只保留当前分数最高的 $k$ 个 Token，重新归一化后采样。
其候选数量有固定上限，易理解，但不考虑分布是尖还是平。
分布很尖时可能保留无用长尾，分布很平时又可能过早删除合理候选。

### 3.4 Top-p

Top-p 将概率从高到低排序，保留累计概率首次达到阈值 $p$ 的最小前缀。
设排序后概率为 $p_{(1)}\ge p_{(2)}\ge\cdots$，集合大小为：
$$k^*=\min\left\{k\mid\sum_{j=1}^{k}p_{(j)}\ge p\right\}$$
分布尖时集合小、平时集合大；Nucleus Sampling 按概率质量而非固定席位截断长尾。

低 Temperature、小 Top-k 和低 Top-p 叠加后可能只剩一个候选；调试应观察最终候选数。

## 4. ops-a 小词表手算

### 4.1 结构支持集先起作用

假设 `ops-a` 正在生成 final 的 `status` 值。
模型对四个完整 Token 给出：
```text
token       degraded  healthy  down  restart
logit          2.4      1.8    0.6     2.8
```

`restart` 原始分数最高，但 $D$ 只允许三个状态。
8.1 提供的结构 Mask 先把它设为 $-\infty$。

### 4.2 $T=1$ 的概率

对三个合法分数减最大值 2.4：
```text
exp values: degraded=1.0000, healthy=0.5488, down=0.1653
sum=1.7141
```
归一化约为：
```text
degraded 0.5834, healthy 0.3202, down 0.0964
```
Greedy 选择 `degraded`。

### 4.3 $T=0.5$

分数差距加倍：
```text
exp values: degraded=1.0000, healthy=0.3010, down=0.0273
```
概率约为：
```text
degraded 0.7528, healthy 0.2266, down 0.0206
```

Temperature 没删除 `down`，只是把它压到约 2.06%。

### 4.4 Top-k 与 Top-p

在 $T=0.5$ 后使用 Top-k=2，会保留 `degraded` 和 `healthy`。
重新归一化约为 `degraded 0.7687, healthy 0.2313`。

Top-p=0.9 也保留这两个，因为第一项 0.7528 未达 0.9，前两项累计 0.9794。
若阈值不高于 0.7528，则只剩 `degraded`。

这个算例说明：
- 结构约束决定哪些状态绝不允许；
- Temperature 调整合法状态间的相对概率；
- Top-k/Top-p 再删除合法集合中的低优先候选；
- 最终只剩一个候选时，Seed 不再产生差异。

## 5. Seed 与复现边界

### 5.1 Seed 控制什么

随机采样可看作伪随机数 $u_t\in[0,1)$ 落入分类分布的某个累计区间。
Seed 初始化伪随机生成器状态：
$$r_0=\operatorname{Init}(\text{seed}),\qquad (u_t,r_{t+1})=\operatorname{Next}(r_t)$$
相同分布、相同 RNG 算法、相同状态推进次数和相同 Seed，才有机会选择相同 Token。
Seed 不固定模型 Logits，也不固定 Processor 的结果。

### 5.2 同 Seed 仍可能不同

逐 Token 重放还要求固定：
- 输入字节、Tokenizer、Template、媒体处理、底座与 Adapter；
- dtype、量化、Processor 顺序、参数与默认值；
- RNG 算法、候选编号、消耗顺序与停止条件；
- 并行规模、Kernel、归约、硬件、Batch Shape 和实现版本。

浮点加法不满足结合律。
接近并列的 Logits 可能因 Kernel 或 Batch 变化交换顺序，随后生成路径完全分叉。

Greedy 不使用随机抽样，也不等于跨环境逐 Token 确定。
它仍受浮点数值和 tie-break 影响。

### 5.3 序列级 RNG

若整个批次共享一个全局 RNG 流，请求加入、取消或 Batch 重排会改变其他请求消耗随机数的位置。
更稳妥的是为每个请求及候选维护独立、可寻址 RNG 状态：
```text
rng = hash(request sampling identity, candidate index)
counter = generated step
```
这能降低调度变化对随机流的影响，但不能消除 Logits 的数值差异。

### 5.4 三种复现目标

**同部署重放**追求逐 Token 一致；**统计复现**要求多 Seed 的分布、质量和延迟接近；
**语义复现**只要求事故状态和关键字段一致。
合同应明确目标层级；`ops-a` 的摘要通常不承诺跨升级逐字相同。

## 6. n、best-of 与 Beam Search

### 6.1 `n`：返回多个随机候选

`n=C` 表示为同一 Prompt 维护 $C$ 条输出序列。
它们可共享 Prompt Prefill 或 Prompt KV，分叉后各有自己的 RNG、Token、状态和增量 KV。
独立候选不保证互异；Temperature 很低或支持集唯一时，分支可能完全相同。

### 6.2 best-of：生成多于返回

best-of 先生成 $B$ 条候选，再按某个得分返回其中 $n\le B$ 条。
未返回候选仍消耗 Decode、KV 和调度，只是成本对客户端不可见。

必须固定：
- 候选采样与排名目标；
- 累计 Logprob、长度处理、EOS 和截断语义；
- 未返回候选释放与整体取消行为。

best-of 不是一个天然质量保证。
若排序目标与事故判断质量不一致，只会更努力优化错误目标。

### 6.3 Beam Search

Beam Search 在每一步保留累计得分最高的 $B$ 条部分序列。
从每条父 Beam 扩展候选后，要在全局子节点中选择新的 Top-$B$：
$$\mathcal B_t=\operatorname{TopB}\{s_{t-1}^{(b)}+\log p(x_t\mid x_{<t}^{(b)})\}$$

它通常是确定性搜索，不等同于 $B$ 次随机采样。
完成 Beam、未完成 Beam、EOS、最小长度和长度惩罚都会影响最终排序。

直接累加 Logprob 偏向短序列，因为每个新 Token 都加入非正数。
长度归一化改变搜索目标，其公式也属于 $P$。

### 6.4 三者的语义区别

`n` 返回多条随机候选，best-of 内部多生成后少返回，Beam 则逐步保留高分部分序列。
三者概率语义不同，不能只替换候选数。

## 7. 分支的 KV 与调度成本

### 7.1 KV 手算

沿用 8.4 的假设：每 Token KV 为 128 KiB。
Prompt 为 1000 Token，若分支能共享 Prompt KV：
$$M_{\text{prompt-KV}}=1000\times128\text{ KiB}=125\text{ MiB}$$

单分支生成 160 Token：
$$M_{\text{generated-KV}}=160\times128\text{ KiB}=20\text{ MiB}$$

4 个分支各生成 160 Token：
$$4\times160\times128\text{ KiB}=80\text{ MiB}$$
总量约为 205 MiB，而不是单分支的 145 MiB。

如果实现无法共享 Prompt KV，4 分支会更贵。
若多个 Beam 暂时共享相同父前缀，可用引用或 Copy-on-Write，分叉后仍要增加独立块。

### 7.2 活跃序列而非请求数

调度器面对的不是“1 个请求”，而是 4 条可运行序列。
分支会增加：
- 模型 Token 行、KV Block 与搜索工作区；
- Beam 父子重排、采样或 Top-$B$ 选择；
- 完成、取消、超时状态和对其他租户的挤压。

因此准入预算应近似按：
$$B_{\text{decode}}\approx C\times L_{\text{max-output}}$$
并叠加 Prompt、Logprob 和搜索工作区，而不是只按请求 QPS。

### 7.3 Beam 的词表选择

宽度为 $B$ 时，每步概念上有 $B|V|$ 个扩展分数。
即使不完整排序，仍要做 Top-$B$、父索引和 KV 重排。
调度器应限制分支、长度与 deadline，防止单请求占满 Batch。

### 7.4 SLO 与取消

多候选可共享 TTFT，却会增加后续 TPOT；等待全部重排时，最慢分支决定完成时间。
但“首个完成”不等于“得分最高”。
若合同是 `n=C`，服务必须返回约定数量；若合同是 best-of 或 Beam Search，也必须完成排名所需的分支，或满足一个可证明剩余分支不可能超过当前最优解的提前终止条件。

只有合同预先定义为 any-of/first-finish，或客户端明确取消整个原请求时，才可在首个结果后停止其余分支。
把 best-of 或 Beam 静默改成 first-finish 等于改变 $P$；取消时则要释放全部 KV、RNG、得分和引用。

## 8. Logprob 观测

### 8.1 Logprob 是哪一个概率

$$\log p_i\le0$$
越接近 0，Token 概率越高。

但“返回 Logprob”必须说明阶段：
- 原始模型 Softmax 或惩罚/偏置之后；
- 结构 Mask 之后；
- Top-k/Top-p 重新归一化之后；
- 最终实际采样分布。

这些值并不相同。
若用于审计或离线评分，接口语义必须锁定并用可控 Logits 测试。

### 8.2 Token 与序列分数

$$\log P(x_{1:L})=\sum_{t=1}^{L}\log p(x_t\mid x_{<t})$$
长序列累加更多非正数，直接比较会偏向短输出。
平均值、长度惩罚或业务重排都会改变目标，必须在目标数据上验证。

### 8.3 Logprob 不是校准置信度

`degraded` 的 Token 概率为 0.8，不代表现实中有 80% 概率发生事故。
它表示在当前上下文、模型与处理策略下，该 Token 的相对偏好。

用于风险决策前，需要目标数据上的校准、阈值评估、分布漂移监控和错误成本分析。
最终权限或告警升级不能只由一个未校准 Logprob 决定。

### 8.4 观测成本

返回每位置 Top-$L$ 候选需要选择、搬运、Token 解码、序列化和网络传输。
若输出 128 Token、每位置返回 20 项，共有：
$$128\times20=2560\text{ entries}$$

即使每项按 32 byte 粗估也约 80 KiB，文本序列化和 Token 字符串会进一步放大。
全词表 Logprob 更可能成为带宽与内存问题。

应限制位置数、候选数和总返回字节。
只关心状态枚举时，观测少量目标 Token 比返回整个词表更经济。

## 9. 运行时失败与降级

### 9.1 典型失败

- **空支持集**：硬规则求交后无候选；明确失败，不能解除约束。
- **数值异常**：全 $-\infty$、NaN 或无效 Softmax；记录 Processor 阶段并停止。
- **参数非法**：负 Temperature、越界概率或不可能分支；准入拒绝。
- **顺序漂移**：升级改变 Processor 或默认值，分布随之变化。
- **Seed 假复现**：RNG、候选编号或 Batch 已变，却承诺逐字重放。
- **分支 OOM**：大 `n`、Beam 和输出上限占满 KV。
- **Stop 跨 Token**：需暂存可能跨 Token 或 Chunk 的后缀。
- **Logprob 泄漏**：候选返回放大响应或暴露不应展示的 Token。

### 9.2 正确失败顺序

准入先检查参数与预算，每步 Processor 后确认存在有限候选。
选择后原子更新 Token、KV、Grammar、RNG 和分支得分。
正常结束、截断、取消与失败必须区分；结构化 final 只在 8.1 接受状态提交。

### 9.3 显式降级

资源紧张时可以在调用方预先允许的范围内：
- 减少 `n` 或 Beam Width；
- 减少返回的 Top Logprobs；
- 缩短最大输出；
- 从内部 best-of 改为返回可用候选；
- 转异步或明确拒绝。

不能静默把随机采样改成 Greedy、改变 Seed、删除结构约束，或改变排序目标。
从 $P$ 改为 $P'$ 就是新合同：
$$\mathcal R'=(I,M,D,P',S')$$

Trace 应记录解析后的实际参数、Processor 顺序、RNG 身份、候选数、结束原因和资源降级。

## 10. 能力边界

采样策略控制的是模型分布到 Token 的选择，不提供事实、业务校准或权限保证。
Greedy 不等于正确，Beam 不等于高质量，多候选也不等于彼此独立或有用。

8.1 的结构约束只定义合法支持集，本节不重复自动机构造。
8.2 的工具授权、8.3 的 Adapter 身份和 8.4 的媒体特征也不会被采样参数替代。

本节不提供完整 API、模型名单、引擎支持矩阵或部署步骤。
具体默认值和可用算法属于版本化实现，生产合同必须记录实际解析结果。

---

## 总结

- Logits 经有序 Processor 组合后才形成实际选择分布，顺序通常不可交换。
- 结构约束先限定支持集，Temperature 与 Top-k/Top-p 只能在合法集合内起作用。
- Greedy 做局部 argmax；Temperature 改尖锐度；Top-k 固定数量；Top-p 固定累计质量。
- Seed 只固定 RNG 起点，逐 Token 复现还依赖输入、数值、Kernel、顺序和调度。
- `n`、best-of 与 Beam 有不同语义，但都会放大活跃序列、KV 和调度成本。
- Logprob 必须注明观测阶段，且不是天然校准的业务置信度。
- 参数冲突、空集合、分支 OOM 与降级都要显式进入合同和 Trace。
