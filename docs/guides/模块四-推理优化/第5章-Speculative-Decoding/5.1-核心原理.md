自回归模型一次只确认一个未来 Token，不是因为 GPU 不能同时计算多个位置，而是因为真实的下一个位置依赖尚未选出的前一个 Token。
投机解码先用便宜的 Proposal 暂时补出未来，再让 Target 并行验证这些已知候选。
它减少的是 Target 位于关键路径上的串行 step 数，不是消除因果关系，也不是保证减少总计算量。

本节只回答两个基础问题：候选怎样经过 Target 验证后仍保持原输出语义，以及一次投机轮次究竟能确认多少 Token。
Proposal 从哪里来留到 5.2 和 5.3，完整性能边界留到 5.4。

## 1. 问题：KV Cache 仍留下串行依赖

设已经确认的前缀为 $x_{<t}$，Target 在位置 $t$ 给出条件分布：

$$p_T(\cdot\mid x_{<t})$$

普通随机生成先采出：

$$x_t\sim p_T(\cdot\mid x_{<t})$$

然后才有资格计算：

$$x_{t+1}\sim p_T(\cdot\mid x_{<t},x_t)$$

第二个条件分布真的包含随机变量 $x_t$ 的实现值；在 $x_t$ 确认以前，系统不知道下一步应沿哪条前缀继续。
KV Cache 保存历史 Token 的 K/V，使后续 step 不必重新计算全部前缀，却没有预先知道 $x_t$，所以没有打断这条数据依赖链。

对当前活跃请求数 $B$、上下文长度 $C$，总览把普通一次 Target 单 Token Decode 时间记为：

$$t_T(B,C)$$

生成四个新 Token 时，普通路径要经历四次依次相连的 Target step。
每个 step 内可以有大量矩阵并行，但四个 step 之间不能任意交换。

低并发 Decode 又常受权重与 KV 搬运限制：一次读取整套 Target 权重，却只为每个请求确认一个位置，计算单元可能没有吃满。
这正是投机解码试图利用的空隙。

> 投机解码不是让 Target 未卜先知地并行生成未来，而是先给 Target 一条或多条假设前缀，让它并行评价“如果这些前缀成立会怎样”。

候选一旦作为已知输入，Transformer 就能借助 causal mask 在序列维同时计算多个候选位置的 logits。
真正需要串行决定的，变成这些候选中哪一段可以提交。

```mermaid
flowchart LR
    P["已确认前缀"] --> D["便宜 Proposal"]
    D --> Y["候选未来"]
    Y --> V["Target 并行 Verify"]
    V --> C["提交合法前缀"]
    C --> P2["新的已确认前缀"]
```

## 2. 机制：Proposal、Verify 与 Commit

一轮线性投机有三个逻辑阶段，本章统一把最大未来深度记为 $K$。

### 2.1 Proposal：建立假设路径

Proposer 从已确认前缀出发，产生候选：

$$y_1,y_2,\ldots,y_K$$

标准随机算法还需要知道逐位置 Proposal 分布：

$$y_i\sim q_i(\cdot\mid x_{<t},y_{<i})$$

$y_{<i}$ 只是候选历史，尚未成为真实输出。
如果第一位后来被否定，依赖它的后续候选也随之失去有效条件。

生成这一批候选的总成本记为：

$$t_D(K,B,C)$$

$t_D$ 可以来自小模型的多次轻量 Decode，也可以来自检索或附加预测结构；本节不比较这些来源。

### 2.2 Verify：Target 为候选位置打分

Target 在同一次验证中计算：

$$p_i(\cdot)=p_T(\cdot\mid x_{<t},y_{<i}),\qquad i=1,\ldots,K$$

如果 $K$ 个候选全部成立，Target 还需要给出候选段之后的分布：

$$p_{K+1}(\cdot)=p_T(\cdot\mid x_{<t},y_{\le K})$$

Target 本轮打包验证的候选位置总数记为 $B_V$。
对固定深度单链可以先用 $B_V\approx BK$ 理解形状，但树分支、变长候选、padding 和 mask 都会改变它。
验证时间统一记为 $t_V(B_V,C)$。

### 2.3 Commit：只接受连续合法前缀

验证必须从左向右进行。
假设前 $j-1$ 位通过、第 $j$ 位首次拒绝，那么本轮只能提交 $y_1,\ldots,y_{j-1}$，再加一个在第 $j$ 位产生的 Target 校正 Token。
$y_{j+1:K}$ 即使碰巧“看起来合理”，也不能继续使用。

原因是原后缀的 logits 建立在：

$$x_{<t},y_1,\ldots,y_j$$

之上，而校正后真实前缀已经变成：

$$x_{<t},y_1,\ldots,y_{j-1},x'_j$$

条件前缀不同，后续分布也就没有可替换性。
若所有候选都通过，且 accepted prefix 尚未触发 EOS/stop、剩余输出配额也允许继续，则从 $p_{K+1}$ 再得到一个 bonus Token。
因此非终止内轮总能确认至少一个 Token，最多确认 $K+1$ 个 Token；终止轮可能在 accepted prefix 内提前结束。

Proposal、Verify、Commit 在实现中可以形成流水，但语义上必须像事务：候选先是暂存状态，只有被接受的连续前缀才能进入已确认历史。

## 3. 标准随机 Speculative Sampling

Greedy 只需比较 Token ID，随机生成却要保持完整 Target 分布。
下面先看当前候选位置，暂时省略位置下标。

设经过采样约束后，Target 的有效分布为 $p_T$，Proposal 的有效分布为 $q$。
Proposer 先抽到候选：

$$y\sim q$$

### 3.1 接受概率

标准接受概率是：

$$a(y)=\min\left(1,\frac{p_T(y)}{q(y)}\right)$$

Proposal 通过“提出并接受 $v$”交付的概率质量为：

$$q(v)a(v)=\min\bigl(q(v),p_T(v)\bigr)$$

接受路径因此只拿走 $p_T$ 与 $q$ 在 Token $v$ 上共有的部分。
若 $p_T(v)\ge q(v)$，Proposal 对 $v$ 给得不够多，提出时可以全部接受。
若 $p_T(v)<q(v)$，Proposal 过度提出了 $v$，只能按 $p_T(v)/q(v)$ 留下。

当 $q(v)=0$ 时，Proposal 根本不会提出 $v$，实现无需计算这个比值。
数值代码仍应显式处理零概率，避免把未定义比值传播成 NaN。

### 3.2 总接受与总拒绝质量

当前位的总接受概率为：

$$\sum_v q(v)a(v)=\sum_v\min\bigl(p_T(v),q(v)\bigr)$$

接受路径交付的不是完整 $p_T$，而只是两个分布的重叠部分。
Target 尚未得到的未归一化质量为：

$$[p_T(v)-q(v)]_+,\qquad [z]_+=\max(z,0)$$

把剩余质量相加：

$$Z=\sum_u[p_T(u)-q(u)]_+$$

$Z$ 恰好等于当前位的总拒绝概率。
因为两个分布的总质量都为 1，Proposal 多出的质量与 Target 尚缺的质量相等。

### 3.3 首次拒绝后的残差校正

若候选被拒绝，不能再从完整 $p_T$ 任意采一次。
接受路径已经交付过重叠质量，从完整 $p_T$ 重采会重复计算那部分。

正确的残差分布是：

$$r(v)=\frac{[p_T(v)-q(v)]_+}{\sum_u[p_T(u)-q(u)]_+}$$

拒绝后从 $r$ 采出的 Token 是当前位的校正 Token。
它补的是 Target 尚未由接受路径拿到的质量，而不是“让 Target 重新考虑一次”。

### 3.4 单位置分布守恒

最终输出当前 Token 为 $v$ 有两条互斥路径。
接受路径贡献：

$$P(Y=v,\mathrm{accept})=\min\bigl(p_T(v),q(v)\bigr)$$

拒绝并校正的路径贡献：

$$P(Y=v,\mathrm{reject})=Zr(v)=[p_T(v)-q(v)]_+$$

两者相加：

$$P(Y=v)=\min\bigl(p_T(v),q(v)\bigr)+[p_T(v)-q(v)]_+=p_T(v)$$

这不是“质量大致相近”，而是理想数学条件下的精确边缘分布。

### 3.5 有效分布到底指什么

$p_T$ 和 $q$ 必须对应算法实际采样时的有效 Token 空间与变换位置，不能随意取原始 softmax。
temperature、top-k、top-p、允许 Token 集合、grammar mask 和其他 logit processor 都可能改变分布。

若接受概率用变换前的 $p_T$，校正却用变换后的 $p_T$，概率质量等式立即失效。
若 Proposal 经过词表映射，$q$ 也必须在最终 Target Token 空间中可解释。

标准算法要求 Proposal 概率可得，不是为了展示 logprob，而是为了计算接受比例和残差。
只返回候选 ID 的 Proposer，必须有与其确定性 Proposal 相符的概率解释，或明确进入另一种非标准质量合同。

## 4. 为什么整段序列仍服从 Target

单位置证明还不够，因为语言模型输出是条件概率链。
整段正确性依赖“从左到右验证、首次拒绝即停止”。

第一位经过接受或残差校正后满足：

$$P(Y_1=v\mid x_{<t})=p_T(v\mid x_{<t})$$

如果第一位候选被接受，它就是本轮的真实第一位。
第二位验证使用的条件前缀因此正好是 $x_{<t},Y_1$，同一个单位置证明可以继续应用。
只要前面候选均被接受，每个被访问的位置都在正确的已确认前缀条件下保持 Target 分布。

若某一位拒绝，残差采样给出该位的正确 Target 边缘，后续候选立即作废。
下一轮从包含校正 Token 的真实前缀重新开始，不会继续沿被否定的候选历史。

因此对任意已提交段 $Y_{1:m}$：

$$P(Y_{1:m}\mid x_{<t})=\prod_{i=1}^{m}p_T(Y_i\mid x_{<t},Y_{<i})$$

右侧正是普通 Target 自回归采样的链式分解。

这份结论依赖四个不可拆开的条件：

1. Proposal 的 $q$ 与实际提议过程一致。
2. 接受概率使用同一位置、同一条件前缀下的 $p_T/q$。
3. 首次拒绝后使用正确残差并终止候选后缀。
4. 所有采样约束在算法规定的位置保持一致语义。

只做到“Target 给每个候选算过 logits”，不能单独证明序列分布守恒。

## 5. Greedy 路径怎样保持等价

Greedy 模式的合同不是保持一个概率分布，而是复现 Target 在同一前缀上的确定选择。
在候选位置 $i$，普通 Target 会选：

$$x_i^\star=\arg\max_v p_i(v)$$

验证时从左向右比较：

$$y_i\stackrel{?}{=}x_i^\star$$

若相等，$y_i$ 可以进入已确认前缀。
遇到首个不等的位置，必须提交 $x_i^\star$，并丢弃所有更深候选。

> 可提交的恰好是 Draft 与 Target argmax 逐位一致的最长连续前缀，再加首次不一致处的 Target 选择；若全一致且尚未触发 EOS/stop 或输出长度上限，则再加一个 Target bonus Token。

这个规则可以归纳证明。
第一位相等时，投机路径与普通路径拥有相同前缀，第二位 Target 因而看到相同输入。
只要此前每位都相等，下一位比较就仍发生在相同条件下。
首次不等时改用 Target 选择，普通路径与投机路径再次对齐，但原候选后缀已不再适用。

“候选概率很高”不是 Greedy 等价条件。
“字符串解码后一样”也不够，因为 KV、stop 规则和后续条件建立在 Token ID 序列上。

严格逐 Token 一致还需要同样的数值与 tie-breaking 语义。
不同 batch shape、浮点归约顺序或并列最大值规则，可能让两个近乎相等的 logits 交换次序。
因此数学上的 Greedy 等价与逐比特复现应分开表述。

随机采样也不能退化成“比较 argmax”；那样会压低 Target 原本赋给其他 Token 的概率质量。

## 6. 算例：从位置存活率得到 A 与 L

本章统一用 $A\in[0,K]$ 表示一轮接受的 Draft Token 数。
第 $i$ 位存活率定义为：

$$s_i=P(A\ge i)$$

$s_i$ 是无条件概率：第 $i$ 位存活意味着前 $i$ 位全部通过。
所以它通常随深度下降，不能用单个平均接受率替代。

非负整数随机变量的尾和公式给出：

$$\mathbb E[A]=\sum_{i=1}^{K}P(A\ge i)=\sum_{i=1}^{K}s_i$$

本章统一教学点为 $B=1$、$K=4$，位置存活率为：

$$(s_1,s_2,s_3,s_4)=(0.80,0.60,0.40,0.20)$$

于是：

$$\mathbb E[A]=0.80+0.60+0.40+0.20=2.0$$

平均候选接受率按总览定义为：

$$\mathrm{AR}=\frac{\mathbb E[A]}{K}=\frac{2.0}{4}=0.50$$

本章教学算例明确限定为：accepted prefix 不触发 EOS/stop，且剩余 `max_tokens` 至少为 $K+1$。
在这种非终止内轮中，提交长度为 $L=A+1$，额外的 1 来自首次拒绝后的校正 Token，或全部接受后的 bonus Token。
终止轮应按实际提交 Token 数统计；若终止条件在 accepted prefix 内触发，则 $L\le A+1$。
因此：

$$\mathbb E[L]=1+\mathbb E[A]=3.0$$

三个量不能互换：

- $\mathbb E[A]=2.0$：平均接受两个 Draft Token。
- $\mathrm{AR}=0.50$：接受 Draft 数占最大深度的比例。
- $\mathbb E[L]=3.0$：一轮平均最终提交三个 Token。

统一时间数值为：

$$t_T=10\text{ ms},\quad t_D=3\text{ ms},\quad t_V=12\text{ ms},\quad t_O=1\text{ ms}$$

一轮投机成本为 $t_D+t_V+t_O=16\text{ ms}$，普通 Target 生成同样的期望三个 Token 约需：

$$\mathbb E[L]t_T=3.0\times10=30\text{ ms}$$

教学点上的 Decode 加速估计为：

$$S_{\text{decode}}\approx\frac{\mathbb E[L]t_T}{t_D+t_V+t_O}=\frac{30}{16}=1.875$$

这个数只用于把正确性与前进距离接到同一量纲，并非性能承诺。
$B$、$C$、$B_V$ 或候选形状变化后，$t_T$ 与 $t_V$ 都可能改变；5.4 将系统性处理这些反转。

## 7. 精确算法与近似算法的边界

“投机解码无损”至少可能指三件不同的事。

### 7.1 严格随机分布不变

使用实际 $q$、$\min(1,p_T/q)$、正确残差分布以及一致的采样变换，最终序列服从 Target 原分布。
这是标准 speculative sampling 的数学合同。

### 7.2 Greedy 路径等价

每个提交 Token 都等于 Target 在同一已确认前缀上的 argmax。
这是确定性路径合同，不是随机分布证明的简写。

### 7.3 显式声明的近似合同

阈值接受、typical acceptance、省略 $q$ 的启发式规则或放宽 Token 一致性，可能改变 Target 分布或 Greedy 路径。
它们可以是有价值的工程选择，但必须单独说明：

- 允许偏离什么；
- 用什么质量指标约束；
- 哪些请求可启用；
- 怎样回退到严格路径。

不能因为近似方法仍有 Target Verify，就把标准算法的“分布守恒”自动转借给它。

## 8. 系统代价与适用边界

正确只说明“可以提交”，不说明“值得这样提交”。
一轮还要承担：

- $t_D$：产生候选；
- $t_V$：Target 验证 $B_V$ 个候选位置；
- $t_O$：采样、调度、mask、通信和候选 KV 状态处理。

候选错误时，Draft 计算、Target 验证和临时候选 KV 都可能成为浪费。
候选全对时，系统也没有免除这些额外工作，只是用一次更宽的 Verify 换掉更多 Target 串行 step。

本节结论最直接作用于 Decode。
若请求是超长 Prefill 加极短输出，即使 Decode 变快，端到端延迟改善也可能很小。

当 Proposal 不提供可解释的 $q$、采样变换不能对齐、候选后缀没有在首次拒绝后作废，或业务使用未声明的近似验收时，都不能声称保持严格 Target 分布。

## 总结

- 自回归依赖要求先确认 $x_t$，才能沿真实前缀计算 $x_{t+1}$；KV Cache 没有消除这条依赖。
- 投机解码先构造候选，再让 Target 并行 Verify，最后只提交连续合法前缀。
- 标准随机算法以 $\min(1,p_T/q)$ 接受候选，首次拒绝后从 $[p_T-q]_+$ 的归一化残差采样。
- 接受质量与残差质量相加恰好恢复 $p_T$，逐位置应用后整段序列仍服从 Target。
- Greedy 等价要求逐位匹配 Target argmax，首次不一致时提交 Target 选择。
- 统一算例中 $\mathbb E[A]=2$、$\mathrm{AR}=0.5$、$\mathbb E[L]=3$，教学加速估计为 $1.875\times$。
