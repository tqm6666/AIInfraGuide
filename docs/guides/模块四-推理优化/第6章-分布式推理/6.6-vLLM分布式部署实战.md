## 1. 三个并行参数的含义

| 参数 | 作用 | 典型约束 |
|---|---|---|
| `--tensor-parallel-size` / `TP` | 层内切分宽度 | 整除注意力头/KV 头等；优先 ≤ 单机 GPU 数 |
| `--pipeline-parallel-size` / `PP` | 层段数 | 总层数可切；跨节点扩展主力 |
| `--data-parallel-size` / `DP` | 副本数 | 复制整实例，扩吞吐 |

GPU 总数需满足：

\[
\#GPU \ge TP \times PP \times DP
\]

（MoE 若启用 EP，再按文档计入专家并行度，见 [6.4](./6.4-数据并行与专家并行.md)。）

🔑 **核心概念**：这三个旋钮对应三种完全不同的扩展轴——**切层内、切层段、复制实例**。设错轴，会出现「能启动但更慢」或「启动即 OOM」。

## 2. 单机多卡：先打通 TP

```bash
# 示例：8 卡装 70B（示意骨架）
vllm serve meta-llama/Llama-3.1-70B-Instruct \
  --tensor-parallel-size 8 \
  --gpu-memory-utilization 0.90
```

Python 等价概念：

```python
from vllm import LLM

llm = LLM(
    model="meta-llama/Llama-3.1-70B-Instruct",
    tensor_parallel_size=8,
    gpu_memory_utilization=0.90,
)
```

启动后立刻检查：

1. 日志里 world size / TP size 是否为 8；
2. `nvidia-smi` 八张卡是否都有相近显存占用；
3. 用短 Prompt 跑通一次生成，确认不是「只在 cuda:0 上跑起来的假多卡」。

📌 **关键点**：单机 TP 是分布式的单元测试。单机都切不匀、跑不通，不要急着上多机（与 6.1「单卡先算账」同构）。

## 3. 多机：TP × PP

假设 2×8 卡，模型需要跨机；Ray 集群已按 [6.5](./6.5-多节点部署Ray.md) 就绪：

```bash
# 概念示例：具体多节点启动方式以当前 vLLM 文档为准
vllm serve <model> \
  --tensor-parallel-size 8 \
  --pipeline-parallel-size 2
```

放置目标：

- 节点 A：PP stage 0 的 TP=8；
- 节点 B：PP stage 1 的 TP=8。

验证重点从「能不能 generate」升级为：

1. rank → node 映射是否符合上表；
2. 段间通信是否走预期网卡；
3. 对比 `PP=1`（若有更大单机）或更小模型代理实验的延迟。

💡 **提示**：多节点第一次建议用**小模型 + 同并行度**打通初始化与 generate，再换大权重，避免每次失败都重新下载/加载数十分钟。

## 4. 横向扩展：DP

当单实例（某组 TP/PP）已稳定，吞吐不够时：

```bash
vllm serve <model> \
  --tensor-parallel-size 4 \
  --data-parallel-size 2
```

含义是：两套 `TP=4` 副本（需 8 GPU）。也可以在 K8s/服务网格层复制多个独立 `vllm serve`，那是更广义的 DP。

注意：

- DP 不会降低单副本显存；
- 要在负载均衡层关注前缀亲和与长连接粘性；
- 验证时应看**系统总 QPS** 与 **P99 延迟**，而不是单个副本的表面繁忙。

## 5. 可执行验收清单

把验收拆成三关；**每一关有可观察的通过条件**，不要停在「端口通了」。

### 5.1 关卡 A：显存与进程（启动正确性）

| 检查项 | 通过条件 | 怎么看 |
|---|---|---|
| 并行度生效 | 日志中 TP/PP/DP 与预期一致 | 启动日志 / engine args |
| 多卡有负载 | 目标 GPU 均有相近显存，而非仅 GPU0 | `nvidia-smi` |
| 提高 TP 后 | 单卡权重占用近似下降 | 对比 TP=4 vs TP=8 空载显存 |
| 开启 DP 后 | 出现多组相似的显存镜像 | 按节点/副本分组看 |

不过关：停在本关，不要做性能结论。

### 5.2 关卡 B：拓扑与通信（放置正确性）

```bash
nvidia-smi topo -m          # NVLink 连接
# 必要时：
NCCL_DEBUG=INFO            # 是否走对网卡/IB
```

| 检查项 | 通过条件 |
|---|---|
| TP 组 | 同组 rank 落在同一节点 / NVLink 域 |
| PP | 跨节点流量符合 Stage 边界预期 |
| 网卡 | NCCL 日志无 docker0/错误 NIC |

不过关：先修 Placement / 环境变量（6.5），再谈吞吐。

### 5.3 关卡 C：性能与 SLO（业务正确性）

固定：同一模型、同一输入分布、同一并发目标、同一 vLLM 版本。

| 指标 | 记录 | 门禁示例（按业务改） |
|---|---|---|
| TTFT P50/P95 | ms | 相对基线不回归超过约定阈值 |
| TPOT P50/P95 | ms/tok | Decode 不被通信拖垮 |
| 输出吞吐 | tok/s | 系统级，非单卡自嗨 |
| 成功率 | % | 无 OOM/超时尖刺 |
| （DP 时）前缀命中 | % | 相对单副本掉幅可接受 |

教学示意（**非某集群实测**）：同 16 卡，`TP=8×PP=2` 能加载，但 P95 TPOT 比「量化后单机 TP=8」差 40%——**验收应判「配置可运行但未达 SLO」**，回头改量化/拓扑，而不是写进容量规划当成功案例。

⚠️ **注意**：**能 serve 不等于配置正确。** 错误的跨节点 TP 也能吐 Token，只是 TPOT 惨不忍睹。

### 5.4 一页勾选版

```text
[ ] A1 日志并行度正确
[ ] A2 目标 GPU 显存均匀
[ ] B1 nvidia-smi topo 符合预期
[ ] B2 rank→node 映射无跨机 TP
[ ] B3 NCCL 网卡正确（多机）
[ ] C1 固定负载对比表已填
[ ] C2 P95 TTFT/TPOT 达门禁
[ ] C3 成功率与（若有）前缀命中可接受
```

## 6. 常见坑与错误配置

| 坑 | 后果 | 纠正 |
|---|---|---|
| `TP` > 单机 GPU 且无足够跨机带宽 | 延迟崩 | 降 TP，升 PP/换机器 |
| 只加 `DP` 想解决装不下 | 每副本仍 OOM | 先 TP/PP/量化 |
| `TP×PP×DP` > 实际 GPU | 启动失败 | 对齐资源 |
| 忽略头数整除约束 | 初始化报错 | 调整 TP 度 |
| 多节点网卡选错 | hang 或极慢 | 设 NCCL 网卡变量 |
| 未做放置约束 | 隐性跨机 TP | Ray Placement / 手动钉卡 |
| 只验收「能 generate」 | 带病上线 | 走完关卡 A/B/C |
| 空载当容量 | 打满即抢占 | 用目标并发测 KV/延迟（[3.4](../第3章-深入vLLM/3.4-调度器源码导读.md)） |
| 多机首次就上满血权重 | 失败成本极高 | 小模型同并行度先通 |
| DP 后不看命中率 | QPS 虚高、Goodput 缩水 | 打点前缀命中（6.4） |

## 7. 推荐实验路径

按下面顺序做，认知成本最低：

```text
1) 单卡小模型 baseline（正确性）
2) 单机 TP=2/4/8（看显存与 TPOT）
3) 固定总卡数对比：TP=8 vs TP=4×PP=2（同机模拟或真多机）
4) 单实例达标后加 DP=2（看 QPS、P99、前缀命中）
5) 记录一份「配置 → 指标」表，作为后续容量规划基线
```

示例记录表：

| 配置 | GPU | TTFT P95 | TPOT P95 | tokens/s | 前缀命中 | 备注 |
|---|---|---|---|---|---|---|
| TP8 PP1 DP1 | 8 | | | | | 同机 |
| TP8 PP2 DP1 | 16 | | | | | 两机 |
| TP8 PP1 DP2 | 16 | | | | | 两副本 |

把表格填完，6.1 的选型原则就会从「口头正确」变成「数据正确」。若同时开投机解码（第 5 章），先固定并行度与量化，再单独开投机对照，避免变量搅在一起。

## 8. 代价与权衡

| 选择 | 收益 | 代价 / 不适用 |
|---|---|---|
| 早上多机 PP | 更大模型可加载 | 验收与运维面变大（6.5） |
| 拉满 TP | 单请求延迟、显存分摊 | Decode 通信；整除/拓扑约束 |
| 广义 DP（K8s 多副本） | 与引擎内 DP 类似扩 QPS | 要自己做粘性与缓存亲和 |
| 严格三关验收 | 少带病上线 | 首次上线更慢（值得） |

适用：已有目标并发与 P95 门禁、能改 NCCL/Placement、愿意先小模型打通。  
若仍在单机假多卡/显存不均阶段，先完成关卡 A，再谈 6.5 的多节点故事。

## 📝 总结

- vLLM 用 `tensor/pipeline/data-parallel-size` 分别控制切层内、切层段、复制实例。
- 实战顺序：**单机 TP → 多机 TP×PP → 达标后 DP**，并用小模型先打通多节点。
- 验收分三关：显存/进程、拓扑/通信、TTFT/TPOT/吞吐与命中率；能 serve ≠ 达标。
- 最常见坑是隐性跨节点 TP、只加 DP 解决装载、以及只看启动不看尾延迟。
