## 本章简介

第 7–9 章把引擎侧的省、快、可测钉住之后，本章解决另一半：**稳定地服务真实流量**——打包与编排、看见与告警、扩缩与路由、从 SLO 反推买多少卡。以 vLLM 为实例，贯穿问题是可运维决策，而不是一份可粘贴的清单 YAML。

**10.1 容器化与 Kubernetes** 讲镜像可复现、GPU 声明与同型号亲和、startup/readiness 覆盖加载长尾，以及滚动窗口里 Ready 容量与冷启动如何一起算账；Production Stack / KServe 只是拼装选项，探针与折损原则不变。

**10.2 可观测性** 把第 9 章 TTFT/TPOT/Goodput 口径接到 Prometheus/Grafana：黄金指标 + 队列/KV 等饱和信号，告警用 `for`、聚合与手册降噪，避免「只告 GPU Util」或告警疲劳。

**10.3 扩缩容与负载均衡** 用 waiting / KV 而非 GPU 利用率做主伸缩信号；粘性会话与前缀感知抬高缓存命中，过载则溢出；网关补齐 TLS、API Key 与限流——引擎默认无认证，禁止公网裸奔。

**10.4 容量规划** 给出从 SLO 与峰值 QPS 反推副本/GPU 的手算表：$Q^{*}$、冗余拆解、显存约束与预热策略，并用 $\$/\text{有效产出}$ 比较「加卡」与「提效率」。

⚠️ **安全提示**：vLLM OpenAI 兼容服务默认不做认证。生产必须在网关层做 API Key、TLS 与网络隔离；本章在 10.3 给出验收清单，避免「裸奔」上线。

## 本章小节

- **10.1 容器化与 Kubernetes 部署**：探针、GPU 资源、滚动发布与冷启动代价
- **10.2 可观测性**：黄金指标、告警降噪，与第 9 章口径对齐
- **10.3 自动扩缩容与负载均衡**：队列深度 vs GPU 利用率；粘性会话与前缀缓存
- **10.4 容量规划**：从 SLO 反推实例数的手算表
