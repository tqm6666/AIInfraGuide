## 1. 这一节要跑通什么

把大模型"搬上线"时，最先碰到的往往不是算法细节，而是三件实事：

1. 环境装得起来；
2. 离线能批量出字；
3. 在线能用 OpenAI 兼容接口被业务调用。

vLLM（UC Berkeley Sky Computing Lab 发起）正是为高吞吐 LLM 服务设计的开源引擎。对本模块而言，它是**实例主线**：第 2 章讲的 PagedAttention、Continuous Batching、Prefix Cache、Chunked Prefill，都会在后续几节落到它的真实组件与参数上。

这一节不展开功能清单式宣传。你读完应能独立完成：

| 目标 | 验收动作 |
|---|---|
| 安装成功 | `python -c "import vllm; print(vllm.__version__)"` 有版本号 |
| 离线推理 | `LLM.generate` / `LLM.chat` 打出合法文本 |
| 在线服务 | `vllm serve` + `curl` / OpenAI SDK 拿到 completion |
| 基础排错 | 遇到 OOM / Chat 乱码时知道先改哪几个旋钮 |

## 2. 和核心技术怎么挂接

跑服务前只需建立一张"**用到了什么**"的地图；机制细节已经在第 2 章讲过，这里不重复深讲。

| 能力 | 你在服务里的体感 | 深入阅读 |
|---|---|---|
| **PagedAttention** | 同样显存能扛更高并发，碎片少 | [2.1 PagedAttention](../第2章-推理引擎核心技术/2.1-PagedAttention.md) |
| **Continuous Batching** | 请求结束立刻腾位，不必等整批齐刷刷结束 | 第 2.2 节 |
| **Prefix Cache** | 共享 System Prompt / 多轮前缀时 TTFT 下降 | 第 2.3 节；V1 工程细节见 3.3 |
| **Chunked Prefill** | 长 Prompt 不再一次性堵死同批 Decode | [2.4 Chunked Prefill](../第2章-推理引擎核心技术/2.4-Chunked%20Prefill%20与统一调度.md) |

用餐厅类比（与 2.1 一致）：旧方式像按"最多可能来 10 人"给每桌预留十人桌；PagedAttention 像把座位拆成可复用的标准块，用多少占多少。你在启动参数里调的 `gpu_memory_utilization`、`max_model_len`，本质上是在改**块池有多大、单请求最多能占多长**——不是让矩阵乘本身突然变快。

💡 **提示**：本节命令与默认值以你安装版本的文档为准；文中写"约 / 常见默认"时，请用 `vllm serve --help` 核对。

## 3. 安装与环境准备

### 3.1 系统要求

| 项目 | 要求 |
|---|---|
| 操作系统 | Linux（推荐 Ubuntu 20.04+） |
| Python | 约 3.10～3.13（以当前文档为准） |
| CUDA | 12.x（NVIDIA GPU） |
| GPU | Compute Capability 7.0+（Volta 及以上） |

### 3.2 使用 uv 安装（推荐）

`uv` 是 vLLM 官方常用的高速安装路径，能按 CUDA 驱动自动选择匹配的 PyTorch：

```bash
uv venv --python 3.12 --seed
source .venv/bin/activate
uv pip install vllm --torch-backend=auto
```

也可显式指定后端，如 `--torch-backend=cu126`。

### 3.3 conda + pip

```bash
conda create -n vllm-env python=3.12 -y
conda activate vllm-env
pip install --upgrade uv
uv pip install vllm --torch-backend=auto
```

### 3.4 AMD ROCm（可选）

```bash
uv venv --python 3.12 --seed
source .venv/bin/activate
uv pip install vllm --extra-index-url https://wheels.vllm.ai/rocm/
```

ROCm 轮子对 Python / ROCm / `glibc` 版本有硬性要求，以官方 ROCm 安装页为准。

### 3.5 验证安装

```bash
python -c "import vllm; print(vllm.__version__)"
```

## 4. 离线批量推理

离线路径适合批量生成、标注、评测：不需要 HTTP，进程内直接出结果。入口是 `LLM` + `SamplingParams`。

### 4.1 基础用法

```python
from vllm import LLM, SamplingParams

sampling_params = SamplingParams(
    temperature=0.8,
    top_p=0.95,
    max_tokens=256,
)

llm = LLM(model="Qwen/Qwen2.5-7B-Instruct")

prompts = [
    "请用一句话解释什么是 Transformer：",
    "Python 和 C++ 的主要区别是什么？",
    "推荐三本深度学习入门书籍：",
]

outputs = llm.generate(prompts, sampling_params)

for output in outputs:
    print(output.prompt)
    print(output.outputs[0].text, "\n")
```

📌 **关键点**：`LLM(...)` 构造时会把权重载入 GPU。常见默认会规划约 **90%** 可用显存给"权重 + KV Cache + 缓冲"（`gpu_memory_utilization≈0.9`，以当前版本为准）。KV 池越大，并发潜力越高，但也更容易在峰值激活时 OOM。

### 4.2 Chat 模式

Instruct/Chat 模型必须走正确的 Chat Template，否则输出质量会崩。

**推荐：`llm.chat`**

```python
from vllm import LLM, SamplingParams

llm = LLM(model="Qwen/Qwen2.5-7B-Instruct")
sampling_params = SamplingParams(temperature=0.7, max_tokens=512)

messages_list = [
    [
        {"role": "system", "content": "你是一个 AI Infra 专家。"},
        {"role": "user", "content": "解释什么是张量并行？"},
    ],
]

outputs = llm.chat(messages_list, sampling_params)
print(outputs[0].outputs[0].text)
```

**备选：手动 `apply_chat_template` 再 `generate`**

```python
from transformers import AutoTokenizer
from vllm import LLM, SamplingParams

model_name = "Qwen/Qwen2.5-7B-Instruct"
tokenizer = AutoTokenizer.from_pretrained(model_name)
llm = LLM(model=model_name)

texts = tokenizer.apply_chat_template(
    [[{"role": "user", "content": "什么是 KV Cache？"}]],
    tokenize=False,
    add_generation_prompt=True,
)
outputs = llm.generate(texts, SamplingParams(temperature=0.7))
```

⚠️ **注意**：`llm.generate` **不会**自动套 Chat Template。裸文本直接喂 Chat 模型，是"输出乱码 / 胡言"的头号原因。

### 4.3 generation_config 覆盖

若模型仓库带 `generation_config.json`，vLLM 可能用它覆盖自身默认采样。想强制用 vLLM 默认时：

```python
llm = LLM(model="Qwen/Qwen2.5-7B-Instruct", generation_config="vllm")
```

## 5. 在线服务部署

在线服务是最常用部署：一行命令起 HTTP 服务，业务只改 `base_url`。

### 5.1 启动

```bash
vllm serve Qwen/Qwen2.5-7B-Instruct
```

默认约监听 `http://localhost:8000`。自定义示例：

```bash
vllm serve Qwen/Qwen2.5-7B-Instruct \
    --host 0.0.0.0 \
    --port 8080 \
    --tensor-parallel-size 2
```

### 5.2 Chat Completions（curl）

```bash
curl http://localhost:8000/v1/chat/completions \
    -H "Content-Type: application/json" \
    -d '{
        "model": "Qwen/Qwen2.5-7B-Instruct",
        "messages": [
            {"role": "system", "content": "你是一个有帮助的助手。"},
            {"role": "user", "content": "什么是 Continuous Batching？"}
        ],
        "temperature": 0.7,
        "max_tokens": 512
    }'
```

### 5.3 OpenAI Python 客户端

```python
from openai import OpenAI

client = OpenAI(
    api_key="EMPTY",  # 未开认证时可占位
    base_url="http://localhost:8000/v1",
)

response = client.chat.completions.create(
    model="Qwen/Qwen2.5-7B-Instruct",
    messages=[
        {"role": "user", "content": "用三句话说明 vLLM 适合什么场景。"},
    ],
    temperature=0.7,
    max_tokens=256,
)
print(response.choices[0].message.content)
```

### 5.4 Completions 与认证

文本补全走 `/v1/completions`。生产建议开 API Key：

```bash
vllm serve Qwen/Qwen2.5-7B-Instruct --api-key my-secret-key
# 或: export VLLM_API_KEY=my-secret-key
```

常用端点：`GET /v1/models`、`POST /v1/chat/completions`、`POST /v1/completions`、`GET /health`。

## 6. 跑通后先动的几个参数

完整调参在 [3.5](./3.5-关键配置调优.md)。入门阶段只需记住四类旋钮：

| 参数 | 你在改什么 | 入门经验 |
|---|---|---|
| `temperature` / `top_p` / `max_tokens` | 采样行为 | 生产常从 `temperature=0.7, top_p=0.9` 试起；要确定性则 `temperature=0` |
| `--gpu-memory-utilization` | KV 池总闸门（常见默认约 0.9） | OOM 先降到 0.8～0.85 |
| `--max-model-len` | 单请求上下文上限 → 每请求 KV 上限 | 按业务真实上限设，不要盲目开满模型标称 |
| `--tensor-parallel-size` | 权重切到几张卡 | 单卡装不下权重时再加 |

带单位的粗算（帮助建立数量级，非精确账本）：

> 假设单卡 80 GB，`gpu_memory_utilization=0.90` → 规划约 **72 GB**。若 7B FP16 权重约占 **14 GB**，剩余量级约 **50 GB+** 给 KV 与运行缓冲。把 `max_model_len` 从 32K 收到 4K，往往比把 utilization 从 0.9 拧到 0.99 更安全——因为你砍的是**每请求 KV 上限**，而不是把显存填得更满。

```bash
vllm serve Qwen/Qwen2.5-7B-Instruct \
  --gpu-memory-utilization 0.85 \
  --max-model-len 4096
```

## 7. 多 GPU：张量并行入门

单卡装不下权重时，优先张量并行（TP）：

```bash
vllm serve Qwen/Qwen2.5-72B-Instruct --tensor-parallel-size 4
```

```python
llm = LLM(model="Qwen/Qwen2.5-72B-Instruct", tensor_parallel_size=4)
```

| 模型规模（约） | FP16 权重 | 常见起步配置 |
|---|---|---|
| 7B | ~14 GB | 1× 24～48 GB 级 GPU 往往可跑（视上下文） |
| 70B | ~140 GB | 约 2×80 GB 起（还要留 KV） |
| 更大 MoE / 405B 级 | 权重大得多 | 多卡 TP/EP，按官方推荐矩阵 |

vLLM 还支持流水线并行、数据并行、专家并行等；入门阶段**先会 TP** 即可。量化（如 AWQ INT4）可把权重大幅压小，再用更少卡服务更大模型——细节放到量化专章。

## 8. 常见问题与排错

### 8.1 启动 / 运行 OOM

```text
torch.cuda.OutOfMemoryError: CUDA out of memory.
```

按成本从低到高试：

```bash
# 1) 降低显存规划
vllm serve MODEL --gpu-memory-utilization 0.8

# 2) 缩短上下文上限（显著减小每请求 KV）
vllm serve MODEL --max-model-len 2048

# 3) 权重切多卡
vllm serve MODEL --tensor-parallel-size 2

# 4) 换量化权重 / 打开量化
vllm serve MODEL --quantization awq
```

### 8.2 Chat 输出乱码或答非所问

优先检查是否走了 Chat Template：改用 `llm.chat`，或手动 `apply_chat_template`。在线路径用 `/v1/chat/completions`，不要把 Chat 模型当裸补全乱打。

### 8.3 国内拉模型慢

```bash
export VLLM_USE_MODELSCOPE=True
vllm serve Qwen/Qwen2.5-7B-Instruct
```

### 8.4 需要 trust_remote_code

```bash
vllm serve MODEL --trust-remote-code
```

### 8.5 服务起来了但很慢 / 经常卡住

| 症状 | 先查什么 |
|---|---|
| 首 Token 极慢、之后还行 | 冷启动、模型加载、长 Prefill；是否该开 Prefix Cache（V1 常见默认开） |
| 出字一顿一顿 | 是否有超长 Prompt 混入；对照 2.4 看 Token 预算（`max_num_batched_tokens`） |
| 吞吐上不去且日志狂刷 preemption | KV 池不够：降 `max_num_seqs` / `max_model_len`，或加显存与 utilization（见 3.4、3.5） |

调试时可临时 `--enforce-eager`（禁用 CUDA Graph），缩小"是图捕获问题还是容量问题"的范围；确认后再关掉以恢复性能。

## 9. 代价与适用边界

| 适合作为默认引擎 | 需要额外评估 |
|---|---|
| 通用 Chat/API、多模型快速接入 | 极端前缀共享 + 强结构约束的 Agent（对照 3.6 的 SGLang） |
| 要 OpenAI 兼容、团队 Python 栈 | 单模型钉死、要在 NVIDIA 上抠极限延迟（对照 TensorRT-LLM） |
| 需要较快跟进新开源模型 | 强绑定非 CUDA 且某后端尚未成熟时 |

跑通服务的代价也很具体：你换来了高并发潜力与生态速度，但要自己消化**容量规划**（KV 池、上下文、并发）和**版本默认值漂移**。下一节开始看这些旋钮落在哪一层组件上。

## 📝 总结

- 入门目标是三条验收：安装成功、离线 `LLM` 出字、`vllm serve` + OpenAI 客户端通。
- PagedAttention / CB / Prefix / Chunked Prefill 的机制挂第 2 章；本节只建立"参数 ↔ 体感"映射。
- Chat 模型务必走 Template；OOM 优先动 `gpu_memory_utilization` 与 `max_model_len`，再考虑 TP / 量化。
- 默认值与后端矩阵随版本变，以当前文档与 `--help` 为准。

## 🎯 自我检验清单

- 能独立安装 vLLM 并打印版本号
- 能用 `LLM` + `SamplingParams` 完成离线批量生成
- 能正确使用 `llm.chat`（或手动 Template）避免 Chat 模型乱码
- 能用 `vllm serve` 拉起服务并用 curl / OpenAI SDK 拿到回复
- 能根据 OOM 症状按顺序尝试降低 utilization、缩短 `max_model_len`、加大 TP
- 能说明 `gpu_memory_utilization` 主要改的是 KV 池容量而非单次算子速度
- 能指出 PagedAttention 细节应回到第 2.1 节，而不是在启动脚本里"调神秘参数"
